| Phần | Quyết định |

| Reset mật khẩu | Dùng coordinator thu hồi bền hiện hành; không lấy phần đổi stamp/thu hồi phiên trực tiếp của nhánh cũ |

| Envelope/key ring | Provider email riêng; ràng buộc ciphertext vào delivery/user/token/loại/mẫu/người nhận; key ring bền, tách cursor/JWT; certificate ngoài Development |
| Migration | Owner-only, additive sau baseline/transfer; checksum và bounded lock; từ chối writer cũ còn kết nối; backfill link/cooldown legacy |
| Bí mật | App Password qua file chỉ Identity được mount; overlay SMTP tùy chọn, không bật gửi trong Compose mặc định |
| Migration/profile/UI cũ và cleanup Identity tổng quát | Không lấy nguyên nhánh. UI mở link và các thay đổi profile còn riêng; cleanup tổng quát phải rà với ledger thu hồi và quyền runtime hiện tại |

PR #28 được thay bằng bản tích hợp chọn lọc. Commit gốc được giữ để truy vết

## Kiểm chứng

Môi trường: .NET SDK 10.0.112, PostgreSQL 18 và Redis 8.2.11 trong container thử
riêng, role Identity/Community/Messaging riêng; `DOTNET_PROCESSOR_COUNT=2`.
Không dùng database dev hoặc gửi thư tới người nhận thật trong các test.

| Bộ | Kết quả |

| Build Release | 0 warning/error |
| Backend toàn bộ | 459/459, 0 skipped |
| Công cụ Python | 42/42 |

| Compose mặc định và overlay email | Cấu hình hợp lệ |

Các ca email kiểm tra: cấp và dùng token đồng thời, mốc 59/60 giây, tài khoản
chưa xác minh đặt lại mà không được xác minh tự động, hai loại token độc lập,
đăng ký đồng thời chỉ commit một delivery, rollback không gửi thư, hai worker,
lease chưa hết/hết hạn, restart với key ring cũ, stale sender, retry/timeout/
lỗi cuối/tối đa 5 lần, gần hết hạn, token bị thay/đã dùng và ciphertext bị
chuyển sang delivery khác. Outbox không chứa email hoặc token thô.

Test Kestrel Identity độc lập chạy worker thật với sender giả: đăng ký không
trả token Development, worker lấy thư, token từ link xác minh được qua API,
sau đó đăng nhập thành công. Password-reset hồi quy vẫn kiểm chứng thu hồi
phiên theo coordinator và Redis/fence. Fixture Community chờ access readiness
sau mỗi restart trước khi bắt đầu assertion về transaction/khóa.

## Giới hạn và vận hành

- Sender giả không chứng minh SMTP Gmail hoặc hộp thư đã nhận. S3-04 tiếp tục
  cấu hình và kiểm chứng gửi thật trên dev; không tự đóng S3-04.
- Link có fragment `/auth/verify#token=...` hoặc `/auth/reset#token=...`; UI mở
  link chưa được nối trong E4-01.
- `ProviderAccepted` là SMTP acceptance; delivered/bounced chưa có callback.
  Timeout sau acceptance có thể gây thư lặp, mỗi token vẫn dùng một lần.
- Token legacy chỉ còn hash: migration giữ policy/cooldown và link hợp lệ,
  không dựng lại raw token hoặc tự gửi email cũ; gửi lại tạo delivery mới.
- Nâng cấp phải dừng/drain Identity trước; Compose migration job và DbMigrator
  từ chối writer cũ còn kết nối. Không chạy bootstrap lên dữ liệu hiện có.
- Key ring email phải giữ qua restart. Không chuyển JWT/cursor sang key ring
  mới, không cấp admin credential cho host hoặc worker.
