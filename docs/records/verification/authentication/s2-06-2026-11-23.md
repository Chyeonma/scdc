# S2-06 — Redis và điều phối thu hồi Identity

**Ngày:** 2026-11-23. **Trạng thái:** hoàn tất triển khai, kiểm thử và nâng cấp volume dev hiện hữu. Nền `6bed091`; kết quả vận hành dev ghi ở [phần nâng cấp](#dev-volume).

## Phạm vi triển khai

- Redis 8.2.11, StackExchange.Redis 3.2.0; hai ACL writer/reader, file qua Compose secrets, AOF always/noeviction, readiness/run_id/generation.
- HTTP JWT, ChatHub, outbox và watchdog đọc phiên qua Redis. Không fallback DB. Snapshot account/session nhất quán; journal version bền và Lua chống ghi cũ, kể cả bigint trên 2^53.
- Permit theo mục đích và owner tin cậy; account/session scopes, peer chỉ cho DM tạo/gửi mới; context tiếp tục operation Community kiểm tra phiên gốc, không lưu JWT ở owner.
- Coordinator lưu ý định có fingerprint bất biến/ACK, cài floor bằng connection owner, deny Redis trước final commit; lease/retry và tiếp tục sau restart. DB chặn sửa payload đã nhận hoặc làm lùi phase/version. Gồm logout, logout-all, thu hồi một phiên, reuse, đổi/reset mật khẩu; audit/outbox cùng commit cuối.
- `202` khi chưa đủ điều kiện commit, GET riêng theo account để đối chiếu; `503` cho kho không xác minh được. Frontend không báo hoàn tất sai hoặc tự dùng lại refresh token chưa rõ kết quả.
- Migration có ledger/checksum Identity, bootstrap từ snapshot offline, journal cho dữ liệu cũ; cập nhật role, CI, Compose acceptance và hướng dẫn.

Thiết kế và cấu hình chi tiết tại [runtime](../../../system/access-revocation.md#s2-06-runtime), [nâng cấp](../../../guides/development.md#s2-06-upgrade).

## Môi trường và bằng chứng

PostgreSQL 18 qua Podman tại cổng 15446; database kiểm thử `scdc_s206_test` với ba role runtime riêng. Redis không ACL ở 16386 cho integration/CI; Redis ACL thật ở 16387 cho vận hành. API thử ở 15447 dùng database riêng `scdc_s206`, file credential riêng và namespace `scdc:auth:fault:`. Không dùng volume dev. Client Node 24 và SignalR kết nối HTTP/WebSocket TCP thật.

Bootstrap/publisher đối chiếu theo lô 128 account để giữ readiness khi journal có nhiều tombstone từ lịch sử.

Các test bao phủ thiếu/corrupt snapshot, run_id cũ, version bigint/generation, timeout owner, mất ACK, restart Identity, đúng phạm vi một phiên, owner/purpose/peer, resuming operation, bảo toàn dữ liệu migration và checksum. Fixture SQL chủ động công bố journal sau khi sửa quyền; clock cursor tách khỏi clock JWT. Các ca tranh chấp reset/login nhận 503 ACCESS_PENDING trong khoảng fencing, rồi kiểm lại token/mật khẩu cũ sau commit để chứng minh không tái sử dụng được.

## Ranh giới bàn giao

Guard transaction và quyền DB chéo tạm vẫn được giữ tới S2-07/08/10/11. Transaction cuối Identity còn khóa user để tuần tự hóa với writer cũ; floor/receipt thật đã có, nhưng chưa tuyên bố writer cũ đã dùng permit. Media chưa tham gia registry. Phép đo trên là DM với lỗi Redis ở môi trường thử, chưa thay kiểm chứng tải, các lỗi authority/clock hoặc toàn bộ mốc thu hồi tại S2-11.

## Nâng cấp volume dev thực — 2026-11-23

Đã nâng cấp database `scdc_chat`, volume Podman **`scdc_scdc-postgres-data`**, project Compose `scdc`. Dừng toàn bộ writer trong lúc migration; giữ `.env` và các volume khóa JWT, Community, Messaging, user-search hiện hữu. Không replay schema/seed trên database dev.

1. Lưu `pg_dump -Fc` trước nâng cấp, quyền 0600 trong thư mục 0700. Khôi phục thử vào database riêng và đối chiếu SHA-256 của toàn bộ dòng tại **46 bảng, 249 dòng**: khớp.
2. Diễn tập S2-03 → S2-04 → S2-05 → S2-06 trên bản sao backup, rồi chạy cùng CLI trên dev. Chạy lại cả bốn migration đều no-op với checksum khớp. Đối chiếu ngay sau migration, trước khi bật writer: mọi dòng gốc giữ nguyên, gồm **6 user, 14 session, 14 message, 3 server, 2 DM, 20 outbox event và 37 audit event**. Outbox đối chiếu qua hợp các owner; audit/ledger đối chiếu tại vị trí mới. Hai bảng Moderation rỗng trước khi bỏ.
3. Dev có ledger Identity tháng 10 (`id/applied_at`) và helper `common.utf16_length_identity_legacy(text)` mà bootstrap thử không có. CLI lưu nguyên ledger thành `identity.legacy_schema_migrations`, chuyển nguyên helper sang Identity; giữ dòng, timestamp, OID và constraint profile. Hai ca regression kiểm tra bảo toàn và từ chối cấu trúc ledger lạ. Không sửa SQL/checksum S2-03 đã phát hành.
4. Cấp ba role và quyền mới; runtime không đọc/ghi ledger mới hoặc ledger lưu trữ. `make init` xử lý nhãn SELinux cho file secret trên máy Podman này; giữ credential và thư mục 0700. Image `backend-tests` bổ sung Python 3 để chạy provisioner ACL thật.
5. Build và chạy stack; `make check ENGINE=podman COMPOSE_ARGS='-p scdc'` đạt, gồm readiness access, gateway, API, database và OpenObserve. Smoke qua gateway cổng 3000 đạt đăng ký/xác minh/đăng nhập/refresh, hai SignalR WebSocket và gửi/nhận DM. Dừng Redis làm hai kết nối ngắt trong **725 ms**, HTTP trả 503, logout đã nhận trả 202. Bật lại Redis: coordinator commit, status riêng theo account; token đã thu hồi vẫn 401 sau lần restart Redis tiếp theo. Restart API vẫn đọc được hai message và giữ trạng thái thu hồi.

Smoke để lại hai tài khoản có tiền tố `s206dev_` và một DM với hai message kiểm thử. Các số đếm bảo toàn ở trên được lấy trước smoke. Stack dev được giữ chạy tại `http://localhost:3000`.

Artifact riêng tại `artifacts/s2-06/dev-upgrade/`: `before.dump`, `backup-verification.json`, `before.json`, `rehearsal.json`, `migration-result.json`, `real-smoke-result.json`, log build/role/check và runner. TRX tại `artifacts/s2-06/results/`. Không commit backup, credential, token hoặc dữ liệu tài khoản. Không có down migration tự động; khôi phục baseline phải dừng writer rồi dùng backup đã kiểm tra.

Tham khảo cấu hình client: [StackExchange.Redis Configuration](https://github.com/StackExchange/StackExchange.Redis/blob/main/docs/Configuration.md). ACL cho ECHO/INFO để client xác nhận kết nối, HMSET cho bootstrap hash nhiều trường; các lệnh topology/pubsub tùy chọn được tắt trong client. Reader vẫn bị chặn mọi ghi, kể cả trong Lua.
